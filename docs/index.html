Your inbox, on your own infrastructure

A native Android and iOS email client for the cloudflare/agentic-inbox Worker. You deploy the backend; the app just talks to it.

View source on GitHub

Bring your own backend

There is no service behind this app. During setup you point it at a Cloudflare Worker you deploy and control, and it authenticates with your own Cloudflare Access service token. Mail, credentials, and cache stay between your device and your Cloudflare account — they never reach a server I operate, because I do not operate one.

What it does

A full email client, not a viewer.

Mailboxes

List, create against the domains your Worker allows, switch between them, and delete.

Threaded inbox

Per-folder threads with pagination, pull-to-refresh, swipe to archive or delete with undo, and multi-select batch actions.

Folders

Inbox, Sent, Drafts, Archive, Spam and Trash, plus custom folders you can create, rename, and delete.

Conversations

Expandable message cards, sanitized HTML with remote images blocked by default, star and read toggles, attachments.

Compose

New, reply, reply-all, and forward. Drafts save locally and resume in the mode you left them in.

Search

Search as you type, filtered by sender, recipient, subject, date range, or read, starred and attachment state.

Works offline

A local Room cache backs the whole app, with optimistic UI so common actions land instantly.

Adapts to the screen

List-detail split view on tablets, a responsive mailbox grid, and full light and dark themes.

Getting set up

You will need a deployed Worker and about five minutes.

  1. Deploy the Worker

    Follow the instructions on cloudflare/agentic-inbox. The app needs no changes to it — it targets the backend exactly as that repo ships it.

  2. Create a service token

    In the Cloudflare dashboard, go to Zero Trust → Access → Service auth → Service tokens and create one. Copy the Client ID and Client Secret straight away — the secret is shown only once.

  3. Add an Access policy

    Open the Access application protecting your Worker and add a policy with the Service Auth action that includes your new token. Without it the token authenticates but is still denied.

  4. Launch the app

    It asks for your Worker URL, the Client ID, and the Client Secret. They are stored in Android Keystore or the iOS Keychain, on the device only.
