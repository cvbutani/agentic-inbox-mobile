# Airmail migration plan

Moves the Compose UI from the previous Material baseline to the Airmail system.

- **Rules:** [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md)
- **Visual reference:** [design/airmail-mock.html](../design/airmail-mock.html) (every screen,
  phone and tablet, light and dark; all mail in it is synthetic)
- **Scope:** visual design, layout, and presentation logic in `sharedUI`. No change to features,
  ViewModels' behavior, repositories, networking, or the backend.

Paths below are relative to
`sharedUI/src/commonMain/kotlin/com/sonicstarsolutions/agentic/inbox/` (tests mirror them under
`commonTest`).

## Ground rules

1. **Test first.** Every phase that adds logic starts with a failing test in `commonTest`. Pure
   logic (grouping, formatting, contrast) is extracted and tested directly, not through Compose.
2. **One phase, one reviewable change.** Each phase compiles, passes
   `./gradlew :sharedUI:testAndroidHostTest`, and leaves the app shippable. Phases 3 to 6 can
   land in any order once 1 and 2 are in.
3. **No behavior change.** If a visual change needs a functional one, stop and flag it. The two
   known cases are listed under "Presentation logic" in Phase 2.
4. **Tokens only.** No hex values outside `theme/Color.kt`; no `Color.copy(alpha = …)`.
5. **Look at it.** Each phase ends with a walk of the touched screens on a device, in light and
   dark, before the next one starts.

## Phase 1 — Theme tokens

Recolors the whole app with no layout change. Lowest risk, highest visible effect.

**Tests first**

- `theme/ColorContrastTest`: for both schemes, every container/on-container pair and
  `onSurface` / `onSurfaceVariant` on `surface` is ≥ 4.5:1; `star` on `surface` is ≥ 3:1. Reuse
  the luminance helper pattern from `ui/components/LabelColorsTest`.

**Changes**

- `theme/Color.kt`: replace every light and dark value with the role table in the design
  system. Keep `Seed = #1D3557`; drop the "generated by materialkolor" comment, the values are
  now hand-set.
- `theme/Theme.kt`: add `AirmailColors(airmailNavy, airmailRed, star)`, light and dark
  instances, a `staticCompositionLocalOf`, and a `MaterialTheme.airmail` accessor. Provide it in
  `AppTheme`.
- Star tint: `colorScheme.secondary` → `MaterialTheme.airmail.star` in
  `ui/components/EmailListItem.kt` and `ui/thread/ThreadScreen.kt`.
- `ui/components/InitialsAvatar.kt`: initials `Bold` → `SemiBold`.

**Done when** tests pass and every screen renders in the new palette with nothing else moved.

## Phase 2 — Shared pieces

Builds the parts later phases consume. Nothing on screen changes yet.

**Tests first**

- `util/EmailDayGrouperTest`: items on the same local day share a group; order inside and across
  groups is preserved; names are "Today", "Yesterday", weekday inside a week, then "3 July", with
  the year once it differs; a message at 23:59 and one at 00:01 fall in different groups; the
  device time zone decides the day; an empty list gives no groups.
- `util/EmailTimeFormatterTest`: `formatClock` returns the clock time alone for any instant.

**Presentation logic (the only non-visual additions)**

- `util/EmailDayGrouper.kt`: pure function
  `group(items: List<T>, instantOf: (T) -> Instant, now: Instant, zone: TimeZone): List<DayGroup<T>>`,
  where `DayGroup` carries the `LocalDate`, the display name, and the items. Generic so the
  inbox list and the thread share it.
- `util/EmailTimeFormatter.kt`: expose the existing private clock formatting as `formatClock`.

**New components (`ui/components/`)**

- `AirmailBand.kt`: `AirmailBand(active: Boolean, modifier)`. `Canvas`, 6dp, stripe geometry
  and motion from the design system. Reads `MaterialTheme.airmail` and `colorScheme.surface`.
- `Postmark.kt`: `Postmark(date: LocalDate, modifier)`, 40dp ring.
- `DayHeader.kt`: `DayHeader(group, unreadCount, modifier)` on the 72dp grid.
- `theme/Dimens.kt`: add the band height and reuse `ListRowDimens.avatarSize` for the postmark.

**Done when** tests pass and the three components render correctly in a preview in both themes.

## Phase 3 — Inbox, drawer, selection

**`ui/inbox/InboxScreen.kt`**

- Top bar: `containerColor = surface`, title in `primary`. Put the bar and
  `AirmailBand(active = state.refreshing || state.loading)` in one `Column` in `topBar`, so the
  band hides and returns with the bar.
- List: group `state.emails` with `EmailDayGrouper` (remembered on the list and the current
  day), emit a `stickyHeader` `DayHeader` per group, then its rows. Keep `key = { it.id }` and
  `Modifier.animateItem()` on rows; key headers by date. Drafts stay above, ungrouped.
- Infinite scroll counts every lazy item, headers included; confirm `InfiniteScrollUtils` still
  triggers on the last page.
- Empty and error branches: replace the hand-built columns with `StatusPane`. The error state
  gets a Retry button (calls `viewModel.onRefresh()`).
- `SelectionTopAppBar`: `containerColor = surfaceContainer`; actions become Archive, Delete,
  overflow (Select all, Label as…, Mark as read, Mark as unread).
- `FolderDrawerContent`: remove the dividers between system folders, custom folders, New folder,
  and labels; keep the "Folders" title, and one divider above Scheduled / Settings.

**`ui/components/EmailListItem.kt`**

- Add a parameter for the time text so grouped lists pass `formatClock` and search passes
  `format`.
- Selection mode: a selected row shows a `primary` circle with a check in the avatar slot;
  unselected rows keep their avatar. Remove the `Checkbox`. Keep the row's click semantics and
  add a selected state description for screen readers.
- A selected row sets snippet, time, and star to `onPrimaryContainer`.

**`ui/inbox/LabelUi.kt`**

- Drawer label dot: 14dp, pastel fill, 2dp ring in the pair's deep color.

**Done when** the inbox matches the mock's Inbox, Navigation drawer, and Selection mode frames;
swipe to archive/delete with undo, long-press select, pull to refresh, and paging still work.

## Phase 4 — Conversation

**`ui/thread/ThreadScreen.kt`**

- Top bar: `surface`; actions become Archive, Delete, and an overflow with labeled items
  "Move to folder" and "Mark as spam".
- Insert a static `DayHeader` between messages sent on different days (same grouper).
- `MessageCard`: sender `titleSmall` + `SemiBold`.
- `AttachmentChip`: remove the `clip` modifier; put the shape on the `Surface` and the
  `combinedClickable` inside it.
- `DraftLabel`: `tertiaryContainer` / `onTertiaryContainer`.

**Done when** the screen matches the mock's Conversation frame; expand/collapse, star, read
toggle, reply actions, move, spam, attachments open and share, and the draft bottom bar still
work.

## Phase 5 — Composer

**`ui/compose/ComposeScreen.kt`**

- Top bar: `surface`; Close, title, Attach, overflow (Send later…, Discard draft). The Send icon
  leaves the bar.
- `AirmailBand(active = state.sending)` under the bar.
- Send becomes an `ExtendedFloatingActionButton` ("Send", send icon) with `imePadding()` so it
  rides above the keyboard. While sending it is disabled and shows a small progress indicator.
- Loading: skeleton rows in place of the centered spinner.

**Done when** the screen matches the mock's Compose frame; send, send later, discard, attach,
From alias choice, Cc/Bcc reveal, suggestions, and draft autosave still work, and the Send button
never covers the last line of the body with the keyboard open.

## Phase 6 — Remaining screens

| File | Change |
|---|---|
| `ui/search/SearchScreen.kt` | `surface` bar; active filters as `secondaryContainer` chips; rows use `format`; no day headers |
| `ui/scheduled/ScheduledScreen.kt` | `Postmark` (send day) in the leading slot; status text in a `tertiaryContainer` chip; "Sending now…" in `primary` |
| `ui/mailbox/picker/MailboxPickerScreen.kt` | `surface` bar; domain names as group titles on the 16dp edge; rows on the 72dp grid |
| `ui/mailbox/settings/MailboxSettingsScreen.kt` | Outlined fields; alias rows with a 32dp avatar; one divider between the profile and alias sections |
| `ui/onboarding/OnboardingScreen.kt` | `AirmailBand(active = state.validating)` across the top in the compact and medium layouts, and across the hero pane in the expanded one |
| `ui/splash/SplashScreen.kt` | New palette only |

**Done when** each screen matches its mock frame and its existing behavior is unchanged.

## Phase 7 — Verify and close

- Walk every screen on a phone in light and dark, then at font scale 1.3
  (`adb shell settings put system font_scale 1.3`, restore afterwards).
- Tablet: `adb shell wm size 2560x1600`, check the list-detail split (open row tint, X to close,
  width caps), then `adb shell wm size reset` and `adb shell wm density reset`.
- iOS simulator: safe areas around the band and the Send button, edge-swipe back, Reduce Motion
  (the band must not slide).
- Android 7.0/7.1 cannot interpolate the variable font, so unread loses its weight cue there;
  confirm the navy time still separates unread from read.
- Refresh store and README screenshots.
- Remove the "Status" note from the top of `DESIGN_SYSTEM.md`.

## Not in this migration

- The AI agent panel, auto-drafts, push notifications, MCP.
- The remaining tablet items (search as a list-detail split, folder dropdown, pointer/hover pass).
- A new app icon. The mock's brand mark is a placeholder.

## Open decisions

1. **Pull to refresh.** The plan keeps the Material pull indicator for the drag and adds the
   sliding band while loading. If both together feel redundant on a device, hide the indicator
   once the refresh starts.
2. **Very old mail.** Day headers give one header per day. In a folder with years of mail that
   is many headers; if it reads as noise, group anything older than 30 days by month.
